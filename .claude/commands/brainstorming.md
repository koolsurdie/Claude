# Brainstorming

## Overview

Turn ideas into fully formed specifications before implementation begins.

**Core rule:** Do NOT invoke any implementation skill, write any code, scaffold any project, or take any implementation action until you have presented a design and the user has approved it.

## Process

1. Explore project context through existing files and documentation
2. Offer visual companion tools if the topic involves visual design questions
3. Ask clarifying questions one at a time to understand purpose and constraints
4. Propose 2-3 different approaches with documented trade-offs
5. Present design sections and secure approval after each section
6. Write design documentation to a specified location
7. Conduct self-review for consistency, completeness, and clarity
8. Have the user review the written specification
9. Invoke the writing-plans skill to create implementation guidance

## Key Design Principles

- Break systems into smaller units with single purposes and well-defined interfaces
- Work within existing codebase patterns rather than proposing unrelated refactoring
- The only skill invoked after brainstorming is writing-plans
